# C4 物理体验（人因）专项

> 当研究对象涉及**佩戴、握持、穿戴、操作负荷**类产品（耳机、可穿戴设备、VR/AR 头显、手持工具、输入设备等）时，在二级编码前先读本文件。
> 目的：把"C4 物理体验"从一个标签类别，做成一条可执行的专项分析路径。

## 为什么单独做这一块

人因问题有三个特性，决定了它需要独立处理：

1. **它常被受访者用身体感受描述，而非功能语言。** 用户说"夹得慌"而不是"夹持力超标"——开放编码时容易被打成模糊标签而丢失信息。
2. **它强依赖场景与时间。** 同一产品在"通勤 20 分钟"和"运动 2 小时"下的物理体验可能完全相反。脱离场景的人因结论基本无效。
3. **它具有累积性。** 短时舒适不等于长时舒适，瞬时压力不等于持续负荷。访谈中用户往往只报告"最难受的那一刻"。

## 维度探针清单

编码时按下表逐维度检查语料中是否出现相关表述。**缺失维度不等于没有问题**——可能只是没被问到，应在局限性中说明。

| 维度 | 关注点 | 语料中的典型表述 |
|---|---|---|
| 压力与夹持 | 接触面压力、夹持力、局部压迫 | "夹得疼""压耳朵""勒" |
| 摩擦与位移 | 滑动、晃动、移位 | "往下滑""总得扶""跑起来会晃" |
| 重量与平衡 | 负重感、重心、下坠 | "沉""往下坠""戴久了脖子累" |
| 温度与排汗 | 闷热、出汗、积汗 | "闷""出汗之后更难受" |
| 疲劳累积 | 随时间变化的不适 | "刚开始还行，一小时以后…" |
| 动作干扰 | 与身体动作的冲突 | "低头会掉""戴着没法戴帽子" |
| 感官负荷 | 声、光、振动的刺激 | "压得耳朵疼""震得发麻" |
| 个体适配 | 体型/头型/耳型差异 | "我头大，不太合适" |

## 链条构建：从症状到后果

人因问题必须写成完整链条，不能只停在症状。**只写"夹得疼"的洞察没有决策价值**——要写清它在什么条件下、导致什么后果。

```
条件（场景 + 时间 + 身体状态）
  → 症状（具体身体感受，带时间量与部位）
  → 行为（用户的应对动作）
  → 后果（弃用 / 降级使用 / 忍耐 / 差评）
```

**示例（引自 `coding-framework.md` 第 9 节）：**
```
运动 + 出汗 + 约20分钟（条件）
  → 耳后夹持疼痛 + 下滑（症状）
  → 频繁手动扶正（行为）
  → 运动场景弃用、换回旧耳机（后果）
```

## 场景与时间必须记录

编码人因语段时，**同时抽取三个参数**，缺哪个标注"未提及"：

| 参数 | 说明 | 缺失的影响 |
|---|---|---|
| 场景 | 通勤/运动/办公/睡眠… | 无法判断适用范围 |
| 时长 | 连续佩戴时长 | 无法区分瞬时不适与累积负荷 |
| 身体状态 | 出汗/静止/戴眼镜/戴帽子… | 无法识别放大条件 |

**这三项缺失时，人因结论只能作为"待验证线索"，不得进入 P0。** 一个不知道持续多久、在什么状态下发生的"疼"，不足以支撑立即处理的判断。

## 常见误判（编码与分级时注意）

1. **把"能忍"当"没问题"。** 用户说"凑合能用"往往意味着已降级使用——这是 2–3 级干扰，不是 1 级。
2. **把单次极端体验当普遍问题。** 一个人说"疼得想扔掉"，在 n=5 的研究里是个案，需标注并验证。
3. **把瞬时感受当长期负荷。** "试戴 5 分钟挺好"不能推断长时佩戴舒适。
4. **忽略适应效应。** 部分用户会"戴久了就习惯"，这不是问题不存在，而是耐受了——应在张力记录中体现。
5. **用形容词强度代替行为证据定级。** 见 `coding-framework.md` 第 6 节：**看行为，不看形容词**。
6. **脱离场景下结论。** "佩戴不适"若不写清场景与时长，无法转化为设计动作。

## 输出要求

人因类主题在报告中的呈现，除洞察五要素外，还必须包含：

- **场景-时长-状态**三参数（缺项须标注）
- **症状的解剖位置**（如"耳根部""耳廓上方""鼻梁"）——位置决定结构改哪里
- **应对行为**（用户自己发明了哪些绕行方式）——绕行方式常直接指向设计机会

## 与主观量表的关系

访谈可产出人因问题的**类型、场景与后果**，但不能替代量化测评。若需确定"夹持力最优区间"这类定量问题，需另行设计主观评分（如单题项舒适度评分）与客观测量（如接触压力测量）的对照研究。

**访谈结果在此处的正确用法是：提出待验证的假设与需要测量的变量，而不是给出数值结论。**
