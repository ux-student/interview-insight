# 常见误用与评审高频问题

## 一、交付前自查清单

### 溯源类
- [ ] 每条结论的原话都能通过编号（`[Sxx]`，多份访谈为 `[Ux-Sxx]`）在 `01_segments/cleaned_text.txt` 中定位
- [ ] 多人研究中"N"与实际处理的受访者数一致，且每个编号都能反查回具体受访者
- [ ] 报告中的"原话"已说明引自清洗后文本（非逐字转写）
- [ ] 没有出现"用户普遍认为""多数用户反映"这类无分母的表述——应写"x/N 名受访者提及"

### 编码类
- [ ] 开放编码中没有结论性词汇（"设计不合理""体验差""需求强烈"都是推断）
- [ ] 同一语义未出现多种标签写法
- [ ] 空白/未回答语段已单独标注，未当作噪声丢弃
- [ ] 新增范畴已在 `decision_log.md` 记录理由

### 分级类
- [ ] 每个影响程度分级都有 `[Sxx]` 证据
- [ ] 没有因形容词强烈而跳级（"特别烦"≠ 4 级）
- [ ] 标"待定"的痛点已写明原因（如证据不足），且未列入 P0
- [ ] "半数为界"的说明已在报告中标注为操作性约定，未表述为统计显著

### 反例类
- [ ] 每个主题都有反例检索结果，含检索范围
- [ ] "未发现反例"附有检索范围说明，不是空白
- [ ] 受访者之间的相反表述已记入张力记录

### 数据类
- [ ] 样本量、招募方式、受访者构成如实填写，缺失项写"待确认"
- [ ] 未编造任何用户信息、引语或统计数据
- [ ] 小样本局限已在第六节声明

## 二、常见误用（会导致结论不可信）

| 误用 | 为什么是问题 | 正确做法 |
|---|---|---|
| 用高频词直接当结论 | 词频统计的是词，不是问题；"耳机"出现 30 次不代表它是痛点 | 高频词仅作检索线索，回到语境编码 |
| 把频次表述为重要性 | 分布广度与影响强度是不同维度 | 分列呈现，优先级按判定规则表 |
| 用"影响×频次"算综合分排序 | 两个不可通约的量纲合并成一个数字，难以解释也无法复核 | 用锚点分级 + 判定规则表 |
| 只写症状不写后果 | "夹得疼"无法转化为设计动作 | 写成"条件→症状→行为→后果"完整链条 |
| 脱离场景与时长说人因问题 | 无法判断适用范围与累积效应 | 记录场景、时长、身体状态三参数 |
| 把个案写成普遍结论 | 小样本下极易发生 | 标注"个案，需验证" |
| 删掉不利证据 | 只收集支持性证据会放大既有结论 | 强制反例检索并记录 |
| 主题名用行业术语 | 用户没说过的词会掩盖真实语义 | 优先采用受访者自己的用词 |
| 报告用百分比呈现小样本分布 | n=5 时"占比 40%"是虚假精确 | 写"x/N"，不换算百分比 |
| 行动建议写"未来可进一步研究" | 不可执行，等于没建议 | 写清做什么、谁做、如何验证 |

## 三、评审 / 答辩高频问题与应答准备

**Q1：你的编码为什么没有报 Kappa？**
> 本工具采用单编码者流程，定位是产品决策场景的快速洞察产出，不承担信度指标报告。若研究需要一致性数据，需改用双人独立编码流程。这是方法选择，不是疏漏。

**Q2：你怎么保证编码不是主观的？**
> 三层约束：开放编码要求标签能在原话中找到对应表述（禁止结论词）；每个主题强制反例检索并公开检索范围；所有分级都有 `[Sxx]` 证据可反查。完整过程留存在 `02_codes/` 至 `04_themes/`。

**Q3：三级编码的依据是什么流派？**
> 编码技术采用 Strauss 与 Corbin 系统化的开放—轴心—选择路径。本工具是编码技术的用研适配，不含理论抽样、理论饱和判定、备忘录与反身性记录——这些属完整扎根理论流程，不在本工具范围内。

**Q4：只有 5 个受访者，结论有意义吗？**
> 小样本不适合推断总体比例，适合发现问题类型与生成假设。报告第六节已声明这一点。若要用访谈结论估计人群中的发生率，需要另行定量设计。

**Q5：为什么优先级不用"影响程度 × 频次"？**
> 两者量纲不可通约，相乘会得到一个看似精确、实则无法解释的分数。本工具改用影响程度 1–4 级锚点（有原话证据）+ 判定规则表，结果可直接复核，且把两个维度的原始值分列呈现给决策者。

**Q6："原话"是逐字转写吗？**
> 不是。预处理移除了语气词与停顿标记，报告中的原话引自清洗后文本，保留语义与用词。如需严格逐字引用，须回 `00_raw/` 原始转写稿取，并在引用处注明。若确需逐字口径，可加 `--keep-fillers` 重跑预处理（保留语气词与省略号），再核对 `00_raw/`；注意保留后文本可读性会下降。

**Q7：如果研究目标和语料对不上怎么办？**
> 应在第 1 步提出。工具要求研究目标、产品主题、样本信息缺失时向用户确认而不是自行假设；若语料无法回答研究目标，应如实说明而非勉强产出结论。

## 四、什么情况下应当停止分析

出现下列任一情况，应停止并回到用户确认，而不是继续产出报告：

- 逐字稿缺少说话人区分，且无法通过 `--interviewer-labels` 指定——这会让"多人提及"被误算
- 样本量或受访者构成完全未知，且用户无法提供
- 语料与研究目标不匹配（如目标是评估可用性，语料全是价格讨论）
- 转写质量差到专有名词无法辨认——误识别会污染多处编码
- 用户要求"直接给结论，不要过程"——这违反本工具的核心约束（结论必须可溯源），应说明并协商
