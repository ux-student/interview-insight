# 三级编码框架（用研适配版）

本文件是访谈分析的方法内核。对访谈文本做结构化洞察时，按「开放编码 → 轴心编码 → 选择编码」三级执行，确保输出是可溯源、可复核的研究结论，而非文本摘要。

## 1. 方法来源与边界

三级编码（开放编码、轴心编码、选择编码）作为**编码技术**，源自 Strauss 与 Corbin 在《Basics of Qualitative Research》中系统化的程序化编码路径。（该书历经多个版本，引用时请核对所用版本：1990 年第 1 版、1998 年第 2 版、2008 年第 3 版为 Corbin 与 Strauss 合著。）

**本框架是编码技术层面的用研适配，不是完整的扎根理论研究流程。** 以下环节不在本框架范围内：

- 理论抽样与理论饱和判定
- 持续比较直至理论生成
- 备忘录（memoing）与研究者反身性（reflexivity）的系统记录
- 编码者间一致性检验（Kappa / Alpha）

若研究目标为理论建构，或需向期刊报告信度指标，请改用完整的质性研究流程，并参考 COREQ / SRQR 等质性研究报告规范。

**这个边界必须在交付物中声明**，不要因为"扎根理论"听起来更有分量而省略它。

## 2. 术语前置说明

- **"原话"指清洗后文本中的原文片段。** 预处理已移除语气词与停顿标记，因此它保留语义与用词，但不是录音逐字的字面转写。引用时标注语段编号可反查回 `01_segments/cleaned_text.txt`；如需逐字字面引用，可加 `--keep-fillers` 重跑预处理，或回 `00_raw/` 原始转写稿取。
- **语段编号**：单份访谈为 `[S01]`；两份及以上为 `[U1-S01]`（受访者号 + 该受访者内序号）。**多人研究必须使用带受访者号的编号**——报告要写"x/N 名受访者提及"，而只有 `[Ux-Sxx]` 才能让读者核对某个语段是否真的出自该受访者。全局连续编号（`[S05]` 不知道属于谁）会让这一核对无法进行。
- **频次指提及分布，不指影响强度。** 本框架不把"提及的人多"等同于"问题更重要"——二者是不同维度，分别记录（见第 6、7 节）。

## 3. 一级：开放编码（Open Coding）

逐句扫描清洗后的文本，为每一个有效表达打标签。

**规则：**
- 只描述、不推断：标签贴近用户原生语义，禁止提前下结论
- 用短语（名词/动词），不用完整句子
- 一个表达可打多个标签；同一语义在不同段落重复出现时复用同一标签（用于累计频次）
- 同时记录情绪强度线索（如"特别疼""完全没法用"），供第 6 节判断影响程度

**通用标签池（可按产品增补）：**
用户属性｜使用场景｜触发时机｜功能评价｜操作行为｜体验痛点｜物理感受｜使用动机｜替代方案｜未满足需求｜改进建议

**反例（禁止）：**
- 用户说"戴半小时耳朵根就疼" → 标签写"产品设计不合理"（这是推断，不是开放编码）
- 正确标签：`佩戴30min耳根部疼痛`

**判据（如何自查是否在推断）：** 标签能否被用户在原文里"读到"？如果标签里的词在原文找不到对应表述（如"设计不合理""体验差"这类结论词），就是推断。标签应当是**用户说了什么**，而不是**这说明了什么**——后者是第三级的工作。

## 4. 二级：轴心编码（Axial Coding）

将开放编码标签按语义关联聚类为主题范畴，并梳理范畴间关系（因果、场景触发、先后顺序）。

**5 大核心范畴（可按研究目标增删；增删须在 decision_log 中记录理由）：**

| 范畴 | 收录内容 | 典型标签 |
|---|---|---|
| C1 用户与场景 | 人群特征、使用环境、触发时机、任务目标 | 通勤场景、运动场景、新手用户、睡前使用 |
| C2 功能体验 | 功能满足度、功能缺失、性能表现、可靠性 | 续航不足、连接不稳、功能找不到、漏音 |
| C3 交互体验 | 操作流程、学习成本、反馈、信息呈现 | 操作步骤多、无提示、误触、看不懂图标 |
| C4 物理体验（人因） | 佩戴/握持/触感/重量/压迫/疲劳/声光刺激 | 夹持过紧、耳根部压痛、重量感、长时间疲劳 |
| C5 态度与期望 | 满意度、对比评价、容忍度、改进建议、潜在需求 | 希望可调节、愿为此付费、凑合能用 |

**关系梳理：** 用"条件 → 行动 → 结果"语句连接标签，例如：
`运动场景（条件）→ 出汗后耳机滑动（现象）→ 需要频繁推回、注意力被打断（结果）`

**一个标签跨范畴时怎么办：** 允许挂在主范畴下并在次范畴留引用，不允许为了"看起来整齐"而丢掉语义。例如"出汗后下滑"同时涉及 C4（物理）与 C2（功能稳定性），应在两处标注同一语段编号。

## 5. 三级：选择编码（Selective Coding）

围绕研究目标，从范畴中提炼核心洞察并输出业务启示。

**每条洞察必须包含五要素，缺一不可：**
1. **结论**：一句话陈述发现
2. **频次/覆盖**：多少名受访者、多少个段落提及（多份访谈时给人数，单份给段落数）
3. **原话佐证**：至少 1 条用户原话（引用，可截取，标注语段编号——单份访谈为 `[Sxx]`，多份访谈为 `[Ux-Sxx]`）
4. **业务启示**：对产品/设计的含义或建议方向
5. **反例检索结果**：该主题的反例语段编号，或"未发现反例 + 检索范围"

**核心故事线：** 用一条主线串起核心范畴，例如"物理佩戴问题在运动场景下被放大，进而影响整体满意度与复购意愿"。

**禁止事项：**
- 无原话支撑的主观判断
- 把单个用户的极端表述包装成普遍结论（须标注"个案"）
- 用频次形容词替代分布描述（写"3/5 名受访者提及"，不写"多数用户反映"）
- 输出"未来可进一步研究"式学术收尾——必须落到可执行建议

## 6. 影响程度分级（1–4 级锚点）

影响程度**不由印象决定，由用户表述中的可观察行为证据决定**。分级时必须标注依据的语段编号。

| 级别 | 名称 | 判定锚点（满足其一即可） | 原话特征举例 |
|---|---|---|---|
| **4** | 阻断级 | 明确导致任务无法完成；涉及安全或健康风险；明确引发弃用、退货、差评 | "后来就不用这个了""换回旧的""不敢再用了" |
| **3** | 严重级 | 需依赖替代方案或手动绕行才能完成任务；显著降低使用意愿 | "只能每次手动推回去""得先关掉再重开才有用" |
| **2** | 干扰级 | 造成中断、额外操作或明显不适，但任务仍可完成 | "有点烦""要多按两下""时间长了会不太舒服" |
| **1** | 可感知级 | 用户提及但未影响任务完成，属偏好或轻微不便 | "如果能……就更好了""不太影响" |

**分级纪律：**
- **不因情绪词的强烈程度直接跳级。** "特别烦"如果用户没说影响任务，仍是 2 级；反过来"还行吧"如果伴随弃用行为，可以是 4 级。**看行为，不看形容词。**
- **分级无证据时标"待定"**，不要凑一个数字。待定项不得进入 P0。
- 分级结果写入 `decision_log.md`，注明每一级的证据来源。

## 7. 痛点优先级判定规则

优先级**不用"影响程度 × 频次"相乘**。相乘会制造一个看似精确、实则无意义的分数——把两个不可通约的量纲合并成一个数字，反而更难解释。

改用**判定规则表**，结果可直接复核：

| 影响程度 | 多人集中提及（≥ 半数受访者） | 少数或个案提及 |
|---|---|---|
| **4 阻断级** | **P0** — 立即处理 | **P1** — 标注为个案，需验证 |
| **3 严重级** | **P1** — 排期处理 | **P2** — 观察 |
| **2 干扰级** | **P2** — 观察 | **P2** — 观察 |
| **1 可感知级** | **P2** — 观察 | 不列入 |

**规则说明：**
- **"半数为界"是小样本下的经验切分，不是统计阈值。** 在报告中应显式标注这一性质，不要表述为统计显著。
- **单份访谈**无法计算人数，按段落分布判断：涉及弃用类行为的段落出现即按"个案"列 P1，并在报告中标注样本局限。
- **P0 必须有明确处理理由**（写在报告第四节的"影响"列），不能只给级别。
- 分布数据（频次/人数）与影响级别**分列呈现**，让决策者能看见两个维度各自的原始值，而不是只看到一个合成结果。

## 8. 反例与张力机制

**每个主题在成立之前，必须主动检索反对它的证据。** 这是本框架与"文本摘要"的分界线。

**执行要求：**
1. **反例检索**：对每个主题，回到 `01_segments/cleaned_text.txt` 主动检索与之矛盾的语段（用户表达了相反体验、相反偏好，或该问题未出现）。结果写入 `04_themes/tension_record.md`。
2. **不允许留空**：未找到反例时，写"未发现反例"并注明检索范围（检索了全部 N 个语段 / 检索了与主题相关的 M 个语段）。空栏位视为流程未完成。
3. **张力记录**：当不同受访者对同一问题表述相反时，记录为张力，并写出**可能的解释**（个体差异、场景差异、期望差异）——解释属候选，需研究者确认。
4. **反例的处置**：反例不要求推翻主题，但要求主题带上边界。例如"3/5 名受访者反馈夹持过紧，另 1 名长期使用者反馈'戴久了能适应'"——这句话比"用户普遍反馈夹持过紧"有价值得多，因为它交代了边界。

**为什么要做这一步：** 只收集支持性证据的分析，会系统性地放大研究者已经相信的结论。反例检索是对这一偏差的强制对冲。

## 9. 完整编码示例

**原始文本（[S03]）：**
"我跑步戴这个耳机，差不多二十分钟吧，耳朵后面这块就开始夹得疼，出汗之后还会往下滑，总得用手去扶，挺烦的，后来跑步我就换回旧耳机了。"

**开放编码标签：**
`跑步场景` `佩戴20min耳后疼痛` `夹持致痛` `出汗后下滑` `需手动扶正` `烦躁情绪` `运动场景弃用` `换回竞品`

**轴心编码：**
- C1 用户与场景：`跑步场景`
- C4 物理体验：`佩戴20min耳后疼痛` `夹持致痛` `出汗后下滑`
- C2 功能体验：`出汗后下滑`（运动稳定性不足）
- C5 态度与期望：`烦躁情绪` `运动场景弃用` `换回竞品`
- 关系链：跑步 + 出汗（条件）→ 夹持疼痛 + 下滑（现象）→ 手动扶正、烦躁（结果）→ 场景弃用、换回竞品（后果）

**选择编码（洞察）：**

> **结论：** 耳挂夹持力与运动稳定性不足，会导致运动用户在场景内弃用。
> **频次：** 单份访谈中于 [S03] 集中出现（多人访谈时替换为"X/Y 名用户提及"）。
> **原话：** "二十分钟吧，耳朵后面这块就开始夹得疼，出汗之后还会往下滑……后来跑步我就换回旧耳机了。" [S03]
> **业务启示：** 夹持力与防滑设计是运动场景的 P0 人因项，建议优先验证耳挂弧度与接触面材质，并在运动场景下做佩戴稳定性测试。
> **反例检索：** 本段所在语料的其余部分未出现与该问题相反的表述；检索范围为该受访者全部语段。若为多人研究，此处须替换为实际检索范围。

**影响程度分级（本示例）：** **4 级（阻断级）**——依据：出现明确弃用行为（"换回旧耳机了"），对应锚点"明确引发弃用"。证据：[S03]。

**优先级（本示例）：** 个案提及 + 4 级 → **P1**，标注为个案待验证；若多人访谈中 ≥ 半数受访者出现同类表述，则升为 P0。
